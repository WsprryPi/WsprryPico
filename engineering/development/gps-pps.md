# GPS UTC, PPS, and reference calibration

Optional GPS reception supplies UTC observations, position, and oscillator measurements to the standalone application. The portable parser, pairing, calibration, and daylight policies have no SDK dependency. The Pico adapter owns one UART receiver and an input-only gated PWM counter with GPIO interrupts for PPS. The normal RF worker retains its local execution authority. No NTP packet is fabricated, and no second clock servo is allocated.

## Wiring and boot allocation

The [validation platform](../../docs/reference/pico-validation-platform.md) connects receive-only QLG3 TX to GP1/UART0 RX at 9600 baud, PPS to GP3, and Si5351 CLK2 to the distinct input-only GP7 loopback. GP4/GP5 carry Si5351 control, and CLK0 carries its RF output. QLG3 VDD and VBAT use 3V3 OUT on physical pin 36; pin 37 is regulator enable. QLG3 has no receiver RX header. The runtime switch is GP14 to physical ground pin 18; the external LED is GP17 to physical ground pin 23.

An absent or disabled GPS configuration initializes no GPS peripheral. Complete saved allocations reject collisions with direct RF, the runtime button, amplifier control, indicator, I²C, the Si5351 loopback/gate, and filter selectors before persistence. UART RX mappings are GP1/13/17 on UART0 and GP5/9/21 on UART1. Optional receiver-configuration TX must use the matching UART: GP0/12/16/28 or GP4/8/20 respectively. QLG3 refuses TX. The E108/GK9501 profile can send the documented finite `PGKC161,1,100,1000` command only when TX is explicitly connected. A failed command relinquishes the peripheral allocation.

Flash operations and runtime BOOTSEL capture bracket interrupt-masked intervals as capture gaps. The input adapter discards queued and latched edges/bytes across each gap, including nested operations, and requires consecutive fresh UTC/PPS pairs before admitting another observation. Existing observations and calibration retain their original ages; a deferred GPIO interrupt cannot renew them. The same boundary applies to ordinary and inhibited firmware, including SDK Bluetooth flash writes.

GPS settings are one optional closed `gps` object in the current Control/1 config/config-update contract. Wiring, receiver, timing, location, and calibration-policy changes latch restart/output inhibition, including an A/B/A save. Saved settings and immutable boot settings remain distinct. A save never proves a connected receiver or valid UTC/PPS association.

## Reception and admission

`time::gps::Parser` bounds a sentence to 160 bytes and one second from its initial `$`. It verifies framing, checksum, supported GNSS talkers, civil date, numeric ranges, navigation status, and coordinates. Supported RMC and GGA sentences contribute independently to time and position. Other checksum-valid sentence types are ignored. A valid RMC can supply time without coordinates; bytes, satellites, or a GGA fix alone cannot establish UTC.

UART bytes use raw monotonic arrival timestamps. PPS uses an input-only gated PWM counter on an odd GPIO, reserving its complete PWM slice separately from Si5351 loopback. The counter starts at the electrical edge; a bracketed timer/counter read removes interrupt-delivery latency from the PPS timestamp. GPIO output enable remains forced low throughout PWM selection. Counter wrap, ambiguous edges, clock changes, an unarmed counter, or a timestamp bound exceeding the configured allowance reject the capture. Rising and falling inputs use peripheral-input polarity selection while physical edge state remains separately observed. The conversion bound includes raw-timer bracketing, two counter ticks, input synchronisation, and a 100 ppm clock-ratio allowance. IRQ latency, its boot maximum, timestamp error bound, and capture rejections are separate telemetry. Fixed queues hold 256 bytes and eight pulses. IRQ work is bounded. Main-core draining merges the queues chronologically and bounds processing to 320 items. UTC pairing uses the first `$` timestamp; two retained pulse/count endpoints preserve the correct association when a sentence finishes after the next PPS edge. Each pulse is consumed at most once, and a capture gap retires both endpoints. Overflow discards the queued prefix and breaks acquisition. UART errors, malformed sentences, discontinuous pulses, and implausible UTC increments cannot bridge an acquisition gap. Cached reads and rejected observations never renew an age.

PPS polarity, signed edge offset, serial delay window, UTC second offset, and physical error allowances are explicit settings. Positive edge offset means the captured edge follows the UTC boundary. The receiver profile remains unqualified until independent evidence establishes which preceding PPS edge an RMC sentence describes. PPS alone supplies no epoch, date, or leap certainty. Two consecutive, consistently associated seconds are required before an observation enters the existing μChrony source history. The servo retains its own acquisition and quality admission. Reference input permits at most three seconds from edge to admission so that late serial sentences can finish across the following edge; the original edge still determines age. Local USB logging can emit bounded `GPS_PPS` and `GPS_COUNT` records with admission, raw timestamps, count, uncertainty, plan and capture identity. These records contain no coordinates or raw NMEA and are excluded from UDP export.

The browser's Capture timestamp error allowance limits the corrected PPS timestamp bound, independently of the Receiver timing error allowance. Reported IRQ latency describes interrupt delivery, not receiver accuracy; correcting it does not establish the receiver's timing error or UTC/PPS association.

The RMC second offset assigns UTC to the selected PPS edge immediately preceding the sentence: 0 uses the sentence timestamp, −1 assigns one second earlier, and +1 assigns one second later. The receiver's association must be independently validated before enabling it.

RMC supplies UTC directly; software does not invent a GPS-to-UTC leap offset. Its two-digit date is admitted only in 2025–2099. This receive-only profile carries no advance leap announcement. It therefore admits no GPS UTC in the five seconds before or after a UTC month boundary. Each accepted GPS clock model has an internal validity horizon at the next boundary minus five seconds. ARM and both physical launch adapters refuse a complete job crossing that horizon, without guessing insertion versus deletion or changing WTP's leap enumeration. An old holdover model cannot become valid merely because time advances into the next month. Fresh associated observations are required afterward.

## One clock discipline

The original μChrony engine owns four 64-sample NTP histories and one 16-sample reference-clock history within a 36 KiB static budget. GPS uses the same source selection, estimation, phase slew, frequency correction, uncertainty propagation, and virtual clock mapping. NTP packet correlation and delay filtering remain specific to NTP. Application arbitration imports the complete resulting model rather than disciplining it again.

Fresh independently compatible sources can combine. A fresh GPS/NTP interval conflict latches disagreement, including when a new NTP reply reveals it. Source expiry cannot clear that conflict. A new GPS comparison with available, independently agreeing NTP evidence, or explicit reference-policy removal, is required. Combination does not refresh the selected source from a newer peer's timestamp. Controller/browser cross-source authority and disagreement checks remain active.

GPS synchronized age is three seconds, with at most one hour of retained-rate holdover and increasing UTC uncertainty from the original accepted observation. NTP's zero-timeout option does not extend GPS or browser holdover. Losing Wi-Fi does not remove GPS. Restart restores neither UTC nor lock. First-party UTC uncertainty remains informational; source age, leap safety, disagreement, ownership, and hardware guards remain mandatory, and explicit external WTP uncertainty budgets retain their meaning.

## Separate oscillator measurements

Qualified PPS intervals measure raw Pico timer error independently from the Si5351 TCXO. Direct RF correction requires register/configuration evidence that the selected RF clock and timer share the oscillator. It is never inferred from an NTP rate fit. Si5351 correction instead measures coherent CLK2 edge counts over accepted PPS-defined intervals. The loopback plan retains its independent nominal frequency and PLL; transmit correction does not retune the measurement output.

The RF owner publishes atomic, generation-bound counter endpoints. A bounded read-only PPS snapshot checks publication coherence, timer bracketing, system/reference clocks, hardware-wrap bounds, capture identity, and plan generation. A changed generation or resumed capture requires a new PPS-defined start endpoint. Qualified GPS uses at least a 12-second RF-owner capture window so that a window starting between PPS edges contains eleven endpoints for a full ten-second calibration. The normal no-GPS capture cadence is unchanged. Prepared Si5351 ownership still pauses capture through cleanup; retained estimates keep their original ages throughout that gap.

Calibration windows span 10–60 accepted UTC seconds. Timer and synthesizer acquisition keep separate first endpoints; a loopback restart cannot truncate the timer history. Count-read timestamps are normalized by the PPS-measured raw-timer ratio, so differences in IRQ delivery delay do not become synthesizer frequency error. Interval bounds propagate both endpoint allowances and count quantization; a 0.1% conversion margin covers the admitted raw-period range. Reported error is signed ppb: positive means the measured oscillator is fast. Endpoint/capture allowances and count quantization contribute to the bound. Neither value is the virtual UTC mapping rate, whose frequency sign/scale uses the reciprocal. Admission requires finite, bounded values and an estimate within the existing ±100,000 ppb correction range. The holdover engineering allowance adds 50,000 ppb of frequency uncertainty per hour without a new measurement; this is a conservative policy assumption, not an oscillator specification or a measured environmental guarantee. Configured maximum age and the 100,001 ppb quality ceiling both apply.

Manual correction remains separate. With automatic correction off, it is the complete correction. With automatic correction on, it is a residual trim, composed as scale factors and rounded once. Missing, expired, unbound, or conflicting automatic calibration refuses preparation instead of silently selecting manual correction. Each accepted job freezes the effective correction, source, and generation; a Type 2/3 WSPR pair retains one calibration across both frames. New learning affects later intents only.

The independently versioned 256-byte correction journal retains its 192-byte payload framing. Cache version 3 replaces the obsolete inert RF-prior slot with separate historical timer/Si5351 values and device/topology/settings, boot, UTC, generation, span, and uncertainty provenance. Old UTC seeds remain readable. A GPS seed requires matching hardware/settings provenance; its broad provisional UTC rate restores no epoch, observation history, freshness, or RF calibration authority. Fresh PPS/count measurements are mandatory before automatic RF correction after restart. Writes remain coalesced, rate limited, and idle/unowned; reset retains the journal's existing domain and interrupted-write behavior.

## Location, schedules, and records

Manual location is the default. GPS location uses a current validated latitude/longitude fix and derives a six-character Maidenhead locator. A stale, invalid, or missing fix withholds new GPS-located standalone WSPR intents; it never overwrites the saved manual locator. The first frame snapshots the locator and fix timestamp for the complete Type 1/2/3 intent, including both frames of a pair. Movement or subsequent loss of position cannot change its encoded second half.

Optional day/night scheduling evaluates the apparent solar horizon at −0.833 degrees using the NOAA solar equations, UTC, and a current valid GPS position. It handles polar day/night directly, with no fictitious sunrise/sunset, terrain, weather, local time zone, or daylight-saving adjustment. It gates autonomous WSPR and keyed-message occurrences within the existing scheduler. Outside the selected interval, or without usable location, no occurrence is admitted or caught up. Accepted jobs retain their local lifecycle. A location-policy wait is not reported as schedule expiry.

At successful ARM, local USB Logging emits three bounded, job-linked records when informational logging is enabled: `TX_TIME` records scheduled UTC, source, original age, uncertainty, and model generation; `TX_LOCATION` records the frozen locator, source, and fix timestamp; `TX_CORRECTION` records the frozen correction, source, generation, observation timestamp, and bound. These location-bearing records are not added to UDP's fixed-template export allowlist. Existing transport sequence/drop accounting applies. Opaque controller-supplied waveforms are labeled `controller_encoded` with unknown locator; firmware does not infer or rewrite their station encoding from local GPS.

## Control and qualification

GET `/api/control/v1/gps` returns a target/revision-bound current Control/1 resource with saved settings, boot-active settings, restart/storage health, and nullable runtime evidence. Serial presence, PPS presence, UTC pairing, position, satellites, candidate association timestamps, rejection/drop/error counters, and separate timer/Si5351 calibration status are distinct. Runtime reads never alter admission. Precise GPS position is available through authenticated control or physical USB; the unauthenticated consumer read catalog excludes the GPS resource. The coordinated Pi and Pico validators require closed fields, exact units/types, supported current descriptors, and matching device/boot/carrier identities before writes. USB management, network authentication, WTP, and journal versions remain independent.

Host tests and ordinary cross-link/resource audits are software evidence. Physical UART/PPS capture latency, receiver-to-PPS association, absolute UTC, and corrected carrier accuracy require their own recorded board/image/clock/path/reference evidence. A typical receiver specification, loopback self-consistency, a good clock fit, and a synchronized host are insufficient substitutes. An external GPSDO combined into an attenuated SDR path is a measurement reference, not a replacement firmware time input.

The [validation record](gps-pps-validation.md) identifies the tested implementation pair, conducted setup, measurements and limits. It separates the completed Si5351 campaign from the selected, unperformed GP2 direct-output test. Source loss/recovery currently has software evidence; no PPS wire removal is required for that GP2 test.
