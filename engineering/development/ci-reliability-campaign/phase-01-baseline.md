# Phase 01 Establish the baseline and accounting

Execute only phase 01 when explicitly invoked. Read and follow the complete
[shared execution contract](README.md#shared-execution-contract) and
[orientation review](orientation.md). This phase is read-only for executable
sources and operational state. Save only authorized campaign evidence and phase
status; do not implement later recommendations or run new tests/builds merely
to fill missing historical measurements.

## Objective and prerequisites

Freeze the current candidate sources and a reproducible audit universe so later
phases cannot improve a percentage by moving its denominator. No earlier execution
phase is required. Recheck current devel and candidate identities without
overwriting an existing branch or synchronizing another task's worktree.

## Work

1. Read applicable instructions and inspect Pico state, current workflow/build
   definitions, recent changes, and directly invoked Pi clients and fixtures.
   Record commit/tree identities, branch relationships, uncommitted diffs and
   relevant untracked-input hashes, dependency pins, and available retained tools.
   Distinguish local remote-tracking refs from server-verified branch tips.
2. Trace the workflow through run.py, setup, CMake/CTest owners, npm scripts,
   imported runners, image validators, bundling/download/publication consumers,
   Read the Docs hooks, and required companion recipes. List actual triggers,
   required/optional/manual contexts, builds without execution, and unused tests.
3. Produce a reproducible DELETE / REWRITE / RETAIN / HOLD inventory with exact
   paths and function/range slices, role, callers, obligations, size, dependencies,
   proposed replacement, and qualification evidence. Reconcile every member and
   category; protected complements may use exact set definitions and exceptions.
4. Separate orchestration from assertions, scenario data, production code,
   generated/vendor material, and documentation. Record ambiguous mixed slices
   explicitly. Freeze physical line/byte/file metrics and active-file rules.
   Count process/suite/compiler/linker/job/matrix executions independently of
   logical cases. Do not call lexical definitions executed cases.
   Identify documentation-only campaign commits separately from executable
   candidate changes; disclose planning-document growth outside active-harness
   reduction metrics rather than treating a new branch SHA as new runtime work.
5. Reverify the 70-to-8 UI-start hypothesis and duplicate client/build candidates
   against actual dispatch. Charge replacements and new regression execution;
   unused-test retirement earns zero reduction credit. Do not assume counts or
   proposed removals in the orientation are current or already qualified.
6. Inspect existing logs with run/attempt/source/toolchain/context identity. Give
   observation windows and denominators for first-attempt outcomes, classified
   failures, explicit reruns, and unresolved intermittent failures. Distinguish
   source changes and different events from equivalent reruns. Separate queue,
   setup, configuration, compilation, execution, startup, artifacts, cleanup,
   critical-path elapsed, and aggregate job spans. Do not invent percentiles,
   warm comparisons, costs, or causal speedups from unlike runs.

## Acceptance and adversarial assessment

An independent reader must be able to reproduce inventory membership, sums,
metric definitions, and source identity from the report. Challenge hidden helper
costs, duplicated savings, inactive content in active denominators, accidental
coverage reduction, and uncertain failure classifications. Correct errors and
reassess. If a complete semantic code denominator or comparable timing baseline
cannot be established, mark that metric unestimable; freeze known quantities and
unknown slices separately rather than manufacturing precision.

No new runtime success is required or claimed here. Specify the smallest future
measurement for each unresolved question and assign it to its owning phase.
Missing historical logs do not authorize executing another phase.

## Handoff

Save the reconciled inventory, source/context map, reliability observations,
separate 50% thresholds/gaps where defined, and outstanding measurement ledger in
the active campaign documentation. Each later phase must report both its local
delta and cumulative delta against this baseline; rebases require explicit
reconciliation, not silent baseline replacement. Report read-only commands and
limitations, update phase 01 execution status truthfully, and stop.
