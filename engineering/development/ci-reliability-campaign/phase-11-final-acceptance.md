# Phase 11 Perform adversarial acceptance and handoff

Execute only phase 11 when explicitly invoked. Read the complete
[shared execution contract](README.md#shared-execution-contract), the surviving
active plan/current technical guides, phase 01's frozen baseline, and accepted
evidence for phases 02 through 10. Review all pending checks, approvals, holds,
and no-change decisions before claiming campaign completion. Do not assume that
prompt review, a commit, or a prior green run establishes implementation acceptance.

## Objective and scope

Establish that the final intended candidate improves or maintains reliable defect
detection and all required assurance, then report efficiency honestly. This is
campaign acceptance, not release, deployment, merge, or hardware qualification.
Use only currently authorized repositories/environments and retained dependencies.

## Work

1. Freeze final Pico and required companion identities, branch/ref availability,
   uncommitted input hashes, dependency/tool versions, current Git state, and the
   exact candidate graph. Verify all required companion changes are available on
   intended paired refs; an unmerged side branch is not delivery on devel/main.
   Preserve unrelated user work and do not reset/stash/clean it to manufacture
   a clean validation checkout. Record any exact inspected candidate-copy method.
2. Reconcile the complete phase 01 obligation/context universe to actual final
   execution. Explain every addition, retirement, optional classification, and
   supported no-change decision. Preserve triggers, frequency, merge gates,
   current strict contract, transport/storage boundaries, crypto, ownership,
   no-write refusal, persistence, inhibition, and independent expected values.
3. Inspect code and result paths adversarially: empty discovery, skipped tools,
   permissive stubs, catch-all retries, late success, unbounded nested I/O, stale
   callbacks, detached descendants, swallowed exits, primary/cleanup masking,
   wrong-source inputs, stale/forged artifacts, self-confirming expectations,
   weakened timing, and artificial file mergers or relocated complexity.
4. Verify deliberate-defect sensitivity for representative affected obligations:
   malformed/current-version admission, identity/revision/no-write refusal,
   session expiry/drafts, cancellation, cleanup/late child failure, resource
   isolation, build invalidation, image identity/inhibition, and result/artifact
   aggregation. Reuse valid existing sensitivity evidence only for unchanged
   candidate behavior; rerun when source or interface changes invalidate it.
   Restore every counterfactual before final positive verification.
5. Run the final required host/native-browser/build/bundle checks appropriate to
   the implemented slices and both actual production network and USB suites using
   the final intended source pair. Preserve independently fresh reproducibility
   evidence. Any final fix invalidates affected earlier results: rerun those
   checks, including both carriers when shared behavior changes, then reassess.
6. Verify current hosted required-check/status/artifact wiring and approved remote
   settings where those are campaign deliverables. Obtain separate authority
   before hosted dispatch or settings mutation. If unavailable, report those
   acceptance gates unresolved; do not substitute local results or old CI links.
7. Reconcile final physical files/code/bytes, active/equivalent files, logical
   coverage, process/suite/compiler/linker/job/matrix counts, and elapsed timings.
   Charge helpers, moved code, regressions, activated coverage, companion edits,
   dependencies, setup, and transfers. Separate local deltas, cumulative deltas,
   mathematical ceilings, estimates, and unmeasurable quantities.
8. Report first-attempt outcomes, failure classifications, unresolved intermittent
   failures, same-context reruns, observation windows, and denominators. Keep
   successful-first-attempt time separate from cumulative execution and elapsed
   through reruns; separate queue delay, cold/warm state, and aggregate spans.
   Do not call different-source runs equivalent or infer repaired flakiness from
   nonreproduction and repeated green runs.

## Acceptance and final report

Fix actionable findings, rerun affected checks, and perform another adversarial
assessment until no actionable findings remain within the authorized scope.
Unresolved required checks, missing intended companion refs, or unapproved
enforcement changes prevent a full completion claim. A justified RETAIN decision
for unsafe/unprofitable optimization is acceptable; an unsupported 50% target is
not a defect to conceal or a reason to weaken efficacy.

Lead the final report with reliability, safety, coverage, and defect-detection
results. Then give separate reduction verdicts, absolute before/after quantities,
percentages/thresholds/gaps where defined, evidence links, the reconciled inventory,
remaining holds, exact commands/results, source identities, and actual repository
state. Distinguish local qualification from hosted CI and all physical evidence.
Do not certify general reliability from a small sample.

Consolidate durable current instructions and retire completed campaign-only
prompts/review narratives under phase 10's process after acceptance and reference
repair. Preserve any handoff still needed for unresolved selected work. Update the
active phase list truthfully. Complete planned documentation consolidation before
freezing final validation inputs where possible. If later cleanup/status commits
change source identity, record that difference and rerun/rebind affected image,
artifact, and source checks; never relabel earlier artifacts as the new revision.
Do not merge, publish, release, deploy, change
hardware/services, or auto-start another task without separate authorization.
