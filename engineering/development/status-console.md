# Contextual transmitter status

The Station Control Transmitter status section presents the current accepted job separately from future standalone work. It uses native controls, system fonts and the embedded page's flat section design. The section leads Station Control and includes output, owner, clock, Wi-Fi and active hostname observations. Reset Pico is available there once unlocked; Wi-Fi/Host has no status or reset section.

## Observations and disclosure

Root control documents carry `contract:"Wsprry-Control/1"`, required on every control mutation. Capabilities negotiate `operations_status:{schema:"operations",path:"/api/control/v1/operations"}`. The authenticated GET returns one bounded operations projection. The current `/api/control/v1/status` and `/api/control/v1/jobs` expose job history, standalone state, a concise network summary and transport observations. The unauthenticated consumer endpoint remains the closed `public-status` projection. Its field set stays minimal. The operator page uses current `public-read` discovery for the existing detailed operations GET while locked; see [public settings discovery](../protocol/Consumer-Radio-v1.md#public-settings-discovery). Accepted message, frequencies, schedules, correction and owner identifiers are read-only public observations; control actions remain authenticated.

The operations resource has exactly `contract`, `schema`, `target`, `job`, `accepted`, `standalone`, `message_schedule`, `next_wspr_start_utc_ns`, `correction`, `reset_allowed`, `network` and `transport`. `target` is the existing member device/boot envelope. `job` uses the existing status shape with an empty `terminal_records` array; history is available through the current status resource. `standalone` uses the existing scheduler status shape, with its duplicated job fields taken from the same captured ServiceStatus. `message_schedule` is the existing schedule body without the separate resource envelope. `correction` is the existing calibration selection or null. `network` on Pico contains only `enabled`, `link_status`, `ipv4`, `configured_hostname`, `mdns_state` and `mdns_reason`; bulk NTP and transport diagnostics stay in their existing resources. `transport` is null. The resource's ETag is the existing opaque management revision.

`accepted` is null without a retained job. Otherwise it contains `mode`, decimal-string `duration_ns`, nullable decimal-string `start_utc_ns`, integer `event_count`, at most four distinct decimal-string `frequencies_nhz`, boolean `frequencies_truncated` and nullable `message`. Message compiler provenance contains `text` (at most 32 characters), decimal-string `frequency_nhz`, `space_frequency_nhz`, `dot_ns`, `dash_ns`, `repeat_gap_ns` and integer `repeat_count`. For DFCW, the supplied primary frequency is Dot and the secondary is Dash, in either orientation; both durations are the accepted element duration. This internal provenance is excluded from the WTP wire format and job digest. Raw RF-event LOAD never supplies it. Frequency summaries are captured once during successful LOAD and survive release of execution event pages. No event walk, execution cursor or new RF-core request is added to status polling.

Engineering station HTTPS, authenticated Consumer-Radio station/AP and physical USB management admit this resource. Engineering field HTTPS omits its capability and refuses the route, retaining its existing basic status and configuration admission rules before clock qualification. No management schema or public shape is extended implicitly. Consumer encrypted requests retain their existing origin, interface, generation, session and delivery bindings.

The page uses one serialized five-second polling loop, at most one application action in flight, existing transport deadlines, request epochs and exact device/boot validation. New-boot engineering observations rebind only after authenticated same-device hostname readback, invalidate old job estimates and require saved-state review; a consumer rebind requires a new login. Failed or malformed reads clear live console values. After 15 seconds without a confirmed observation, the page marks state/output unavailable and disables controls. Session loss clears privileged rendered readbacks while preserving form drafts. Polling never copies observed data into edited forms, writes journals, claims ownership or submits jobs.

The panel omits browser-local time, Pico UTC, observation timestamps and the engine identifier. Device UTC and the browser observation timestamp remain internal inputs to scheduling, progress and freshness checks. Routine state explanations are omitted; recovery guidance is visible when required, and headline transitions retain the accessible live announcement. Hostname displays confirmed active readback rather than discovery state or a saved name awaiting restart. Discovery conflict and failure guidance remains visible only when actionable.

## State interpretation

Output/storage faults take headline precedence. Accepted loaded, armed or running work follows, independently of incomplete standalone configuration or future-schedule blockers. Running RF-off observations remain active jobs, including keyed gaps. Future context distinguishes recovery barriers, pending durable pause, reset requirements, suspension, paused/expired schedules, clock admission, incomplete WSPR configuration, reserved ownership and an eligible future occurrence. A disabled saved message schedule does not mask enabled WSPR.

Next transmission shows only the mode and available saved message for an eligible enabled automatic occurrence. The item is hidden when schedules are disabled or no next occurrence is confirmed. It consumes the existing device-computed candidate without predicting new slots in the browser. An enabled recurring message schedule owns recurrence authority and suppresses standalone WSPR, regardless of their saved start order. A blocked message schedule does not expose WSPR as a fallback. Accepted jobs retain their separate presentation and lifecycle when future schedules are disabled. WSPR is labelled by mode because this projection does not provide its encoded message.

QRSS labels Carrier, FSKCW labels Space and Mark, and DFCW labels Dot and Dash using accepted compiler values. Saved recurring message context is explicitly labelled separately from accepted work. Message copies and their gap belong to one finite job; recurrence interval, first UTC anchor, optional expiry and next eligible occurrence describe separate jobs. Generic externally loaded jobs report nominal RF events and unavailable original text. WSPR frame counters appear only for the matching scheduler job.

Elapsed duration and percentages use the device UTC at observation and the accepted start/duration. They are estimates, including at 100 percent, and never replace a running state with completion. Character progression remains an unimplemented enhancement; an authoritative event cursor is unavailable. The panel shows only the selected manual correction for the next preparation, as a number with three decimal places under Manual RF correction (ppm). The underlying accepted-job correction remains the engine's frozen preparation selection. Missing values remain unavailable. μChrony disciplines UTC and supplies no RF calibration measurement.

## Reset Pico

The Station status button invokes the existing guarded operation with a product confirmation. Reset is a normal restart retaining saved settings; enabled schedules may resume after readiness checks, while consumed occurrences remain skipped. It does not erase credentials or perform a factory reset, and introduces no new reboot policy.

The request remains `POST /api/control/v1/restart` with the closed empty body `{}`, current If-Match and `features.restart` negotiation. Authentication, target/boot readback, revision consumption, response acknowledgement, transaction token and deferred restart remain the existing authority. Eligibility is checked on receipt and again at delivery: no loaded/armed/running/faulted job, owner, active/unknown output, maintenance, unhealthy storage, hardware-application failure, pending message pause or recurring recovery barrier is permitted. A newly acquired owner or active job cancels the deferred effect. RF-off keyed gaps cannot make reset eligible.

The browser revalidates the same fresh observation after confirmation and after hostname/configuration readback. Expiry cancels before submission with explicit guidance. It submits once, including an ambiguous response, and monitors for at most 90 seconds. Page reachability or a public boot change cannot confirm success. Confirmation requires authenticated readback of the same device and a new boot, with the intended saved hostname applied. Cancellation, logout, timeout, stale revisions and lost replies never trigger an automatic retry. An unconfirmed reset stays unconfirmed until that readback.
